# 会话临界与打断验证

- 日期：2026-10-12
- 范围：`箭牌h5平台` 一轮对话的结束点，以及新一句对上一句 TTS、字幕、卡片的打断
- 服务：本机 `http://127.0.0.1:8912`，`IOT_MODE=mock`

## 结论

新的一句会先停掉上一句的播报，再领取新的回合代号。上一句迟到的字幕、卡片和固定播报都不再进入当前对话。索要 device ID、name、CMD 的句子在服务端就被滤成空正文，页面收到空正文后再停一次播报。

## 场景

1. 打开会话，连续领取两个回合代号。
2. 用第一个代号提交最终回答「可以下发」。
3. 用第二个代号提交产品问答「AKB 1357 是箭牌智能马桶的一个型号。」
4. 再用第二个代号提交「请提供 device ID、name 以及 CMD 操作指令」。
5. 另有不连房间的回合脚本：第一句还没结束时发第二句，第一句的文字和 `[E]:[CMD]:[TEXT]` 播报被丢弃，第二句的回答留下。领新代号的空隙里回来的旧回答同样丢弃。

## 结果

| 检查 | 结果 |
| --- | --- |
| `npm run check` | 通过。`selfcheck ok`，`turn-gate ok`，语法检查通过 |
| 回合代号 | 1 前进到 2 |
| 上一句 `/api/frame` | `superseded: true`，卡片为空 |
| 当前句正文 | 保留「AKB 1357 是箭牌智能马桶的一个型号。」 |
| 索要字段的正文 | 返回空字符串 |
| 打断脚本 | 第一句播报不进入对话，第二句回答和播报留下，随后的意图回合也只收自己的结果 |

## 边界

这次没有进真实 BRTC 房间，没有听到 TTS 实际停掉。`[B]` 是官方示例里的打断帧，页面在新一句开始时发送，并暂停本地已经挂上的 audio、video。房间是否立刻停播，要在已授权的通话里再听一次。
